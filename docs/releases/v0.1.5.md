# phobos v0.1.5

Released 2026-10-21. Completes the reviewed daemon integrations and fixes the
USB-cache and startup-readiness failures found on the real Forge-X printer.
Requires Zig 0.17.0; the Moonraker reference remains pinned to `900848584374`.

## Changes since v0.1.4

- Klippy requests release Core before blocking writes and waits. Owned remote
  tasks, cancellation and teardown are bounded. Public ready is published only
  after the handshake opens the proxy gate, preventing an initial ready/503 race.
  Client subscriptions replace previous selections and filter requested fields.
- HTTP JSON-RPC and WebSocket access enforce authentication and trusted-proxy
  rules. Logout and user deletion revoke WebSocket sessions. Persistence and
  allocation failures preserve owned state rather than losing existing records.
- WebSockets assemble fragmented messages up to 10 MiB, with bounded reads,
  writes and header deadlines. Extension agents support bidirectional RPC,
  remote methods, events and disconnect cleanup.
- MQTT 3.1, 3.1.1 and 5 support acknowledged publishing, temporary subscriptions,
  credential templates and selected Klippy status topics. Sensors sample once
  per second and retain parameter/history metadata. Spoolman tracks extrusion
  and retries retained filament-use reports. See [MQTT](../MQTT.md).
- File management writes thumbnail images, creates streaming ZIP archives,
  queues requested uploads while busy and can observe external changes through
  bounded inotify watches. Checked roots, atomic replacement and bounded metadata
  caching protect existing files. See [file management](../FILE_MANAGEMENT.md).
- Machine providers poll service state outside Core. USB names use a validated
  `usb.ids` cache; auxiliary `BIAS` records no longer break enumeration. V4L2
  queries enumerate discrete camera modes, and CAN queries use bounded native
  I/O. See [machine providers and peripherals](../MACHINE.md).
- Web/ZIP updates stage validated bundles, support rollback and restart configured
  managed services. Git commands and refreshes have bounded lifetimes; tests use
  local temporary repositories. See [updates](../UPDATES.md).
- Power hooks and GPIO buttons, WLED startup/state handling, persistent TD-1
  readers and PanelDue serial commands are connected to daemon lifecycle events.
  Analysis can execute estimates through an injected runner. See
  [power and buttons](../POWER_BUTTONS.md) and [analysis](../ANALYSIS.md).
- Startup parses configuration once and retains it until component teardown.
  Webcam URLs use local network state. Worker shutdown joins outstanding work,
  CLI output reaches stdout, and fresh checkouts include the pinned SQLite
  sources needed to build the static binary.

## Verification

- The final host suite passes 1717 tests, with one gated real-Klippy skip and
  zero failures; 325 bounded fuzz harnesses are discovered. Earlier guided
  WebSocket/MQTT runs completed 70,334 inputs, and Python tooling passed 88 tests.
- Static Cortex-A7 ARM ReleaseSmall code ran inside the real Forge-X 1.4.2
  chroot on `127.0.0.1:7126`, using a copied database and private writable data.
  The final 11 hardware check groups passed, including a cold startup whose first
  object query after public ready succeeded without retrying a 503.
- Hardware checks covered 26 configured components, directory capacity, seven
  USB devices, camera formats/resolutions, three UARTs, 100 reads at concurrency
  two, temperature sampling, fragmented and raw WebSockets, extension-agent RPC,
  thumbnail/ZIP fixtures, error codes and a 3376096-byte G-code download matching
  production's SHA-256. See the [verification ledger](../PROVENANCE.md).
- API name coverage is 123/123 endpoints, 130/130 methods and 27/27 notifications.
  Name coverage does not prove complete behavioral parity. The curated API and
  client documents were reconciled during the review, without changing the pin.
- The probe was stopped and removed, leaving no listener on 7126. Production
  phobos v0.1.2 remained ready on 7125, with the last print complete and both
  heater targets zero. The board boot ID was unchanged. Hardware verification
  preceded the package-version bump; the release changes no further runtime code.
  This release is not installed onto the printer.

## Retained differences and limits

| Classification | Behavior and reason |
| --- | --- |
| Code bugs, fixed | Premature public ready, rejected auxiliary USB-cache records, transport stalls, authentication gaps, ownership failures and incomplete daemon lifecycle wiring. |
| Identity, kept | API 1.5.0 and `moonraker_version: phobos` identify the implementation and vendored API pin rather than Forge-X's older API 1.4.0. |
| Identity, kept | Python fields remain explicit stubs. Git status retains the pinned implementation's name and eight-digit abbreviation. |
| Deliberate behavior, kept | Missing CAN interfaces return an empty UUID list. Reboot and shutdown stay no-ops; the daemon does not execute apt or pip. |
| Environment | This printer has inotify disabled in its kernel and selects observer `none`. An explicit inotify configuration fails startup when unavailable. Probe history age and connection counts differ from production. |
| Configuration | Optional components remain implemented when registered, even when Forge-X omits them. Optional physical devices absent from the actual configuration were not hardware-tested. |

Full Jinja2, LDAP and Apprise remain outside scope. Estimator and package execution
require injected runners. Libcamera enumeration, GitHub rate-limit telemetry,
reverse-DNS authorization, selected power drivers and automatic analysis retain
the limits listed in [TODO.md](../../TODO.md). No current performance claim is
made from historical measurements. Graphify was unavailable and was not updated.

No production deployment, printer restart, motion, heating, print start, firmware
restart, real update, board reboot or shutdown was performed for this release.
