# phobos v0.4.4

This patch release lets a host-started Forge-X daemon see web and ZIP clients
that are installed inside the Forge-X chroot. [v0.4.3](v0.4.3.md) stopped the
repeat 3MF print start. The update screen on an AD5M marked Fluidd, Mainsail
and Guppy Screen invalid after that release.

## Changes

Moonraker runs inside `/data/.mod/.forge-x`, and its config names client paths
from that view: `/root/www/fluidd`, `/root/www/mainsail`, and
`/root/guppyscreen`. Phobos runs on the host. Those directories are not there,
so the install check failed and Fluidd showed the clients as invalid. The
versions it displayed came from the cached Moonraker record.

An absolute update path that does not exist on the host is now resolved at the
same path under `/data/.mod/.forge-x`. A path that exists on the host stays
there, so a bind-mounted repository such as Forge-X or Klipper is unchanged.
Git commands and web or ZIP installs use the resolved path. A missing path in
both places is still invalid.

## Verification

The test suite passes in Debug, ReleaseSafe, and ReleaseFast: 1,810 passed,
one gated real-Klippy skip, zero failures, and 343 bounded fuzz tests per mode.
A new test resolves `/root/www/fluidd` through a stand-in chroot and keeps a
path that already exists.

The same change was installed on the AD5M before this tag. After restart,
`/machine/update/status` reported Fluidd v1.38.0, Mainsail v2.19.0, and Guppy
Screen 0.1.0 as valid. Klippy was ready and the printer was idle.
