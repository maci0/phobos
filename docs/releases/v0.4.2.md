# phobos v0.4.2

This patch release keeps Klipper's own error text when a proxied printer
command fails. A print start that Klipper refuses with `SD busy` now reaches
the slicer as that message. [v0.4.1](v0.4.1.md) answered every such refusal
with `Klippy request failed`.

## Changes

`printer.print.start`, pause, resume, cancel, restart, firmware restart,
emergency stop, and the other proxied Klipper endpoints return HTTP 400 with
Klipper's `error.message`. A string `error`, and an error object with no
message, still use Moonraker's `Malformed Klippy Response`. The same text is
returned over JSON-RPC. A rejection that never captured a message keeps that
Moonraker fallback.

The virtual SD card is still Klipper's. `SD busy` means a print file is loaded
and its work timer is running, including the short gap after a print finishes
or is cancelled. This release reports that condition. It does not clear the
timer.

## Verification

The test suite passes in Debug, ReleaseSafe, and ReleaseFast: 1,807 passed,
one gated real-Klippy skip, zero failures, and 343 bounded fuzz tests per mode.
A new test sends a print start that Klipper answers with `SD busy` and checks
the HTTP and JSON-RPC bodies. It failed before the fix.

The message has not been checked against a slicer on a printer. The `SD busy`
console line and the Orca Slicer dialog `Klippy request failed` were observed
together on an AD5M running phobos.
