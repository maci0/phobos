# phobos v0.4.5

This patch release makes a repeated start of the file already printing return
success. [v0.4.4](v0.4.4.md) sees Forge-X clients inside the chroot. Orca
Slicer showed HTTP 409 `Printer is busy` after a print that had started.

## Changes

An upload with print requested starts the extracted gcode. Orca then sends
`printer.print.start` for the same name. v0.4.3 answered that second start
with HTTP 409 so Klipper would not receive another `SDCARD_PRINT_FILE`. Orca
treats the 409 as a failed upload and shows the error dialog. The first start
has already opened the file.

A start of the file accepted in the previous two seconds, or of the file that
is printing or paused, now returns `ok` and sends nothing to Klipper. The
`.gcode.3mf` archive name matches the extracted gcode. A different file while
a job is active is still HTTP 409.

## Verification

The test suite passes in Debug, ReleaseSafe, and ReleaseFast: 1,810 passed,
one gated real-Klippy skip, zero failures, and 343 bounded fuzz tests per mode.
The repeat-start test starts `bracket.gcode` and then `bracket.gcode.3mf`.
The second response is `ok`.

The reported print was `back_PLA_1h51m.gcode` on the AD5M. Its gcode store has
one `SDCARD_PRINT_FILE`, then `File opened` and `START_PRINT`. The printer was
printing when this was tagged, so the daemon was not restarted.
