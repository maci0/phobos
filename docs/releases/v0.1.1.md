# phobos v0.1.1

Released 2026-10-19. Requires Zig 0.17.0. Moonraker reference remains pinned to
`900848584374` (`0.10.1.dev20`); the compatibility API remains 1.5.0.

Temperature history now samples cached Klippy readings once per second, including
unchanged sensors. Partial status updates preserve target and power readings;
values round to two decimals and each field respects `temperature_store_size`
(default 1200). The daemon owns and joins the sampler. Tests tick it synchronously.

Update status reads Moonraker's persisted `update_manager` cache without fetching
or refreshing remotes. It restores current, remote, and rollback versions, commit
hashes, and deployment state. Git short versions omit the hash suffix while
`full_version_string` preserves it. Unconfigured built-in deployments report empty
objects; the unsupported `repo_detected` field is removed.

Forge-X configuration handling includes the simple machine provider, trusted
clients and proxy headers, hidden Klippy objects, configured webcams with stable
instance UUIDs, file exclusions, announcement subscriptions, and configured update
sources. `-d` selects the data directory's config and database; file roots resolve
symlinks. System information reports the chroot distribution, ARM machine name,
zero serial, and network interfaces correctly. Klippy heater subscriptions seed
the store, and existing Klipper docs/config roots become available read-only.

HTTP returns 404 for websocket-only paths regardless of verb, 404 for a missing
database namespace, and 400 for missing thumbnail filenames or webcam names.
REST and JSON-RPC preserve the public missing-argument and namespace messages
without exposing tracebacks.
Public database access hides private auth records, honors stored forbidden and
protected namespace policies, and includes registered empty namespaces. Config
webcams remain in memory rather than creating a database namespace. OctoPrint
reads live connection state and cached heater temperatures.

Parity changes also include Feather remote-method dispatch and
idle checks, PanelDue line parsing without opening a serial device, and injected
estimator/package command hooks. Package execution needs an injected shell; the
default runner rejects apt and pip. Estimator execution also requires an injected
shell. Web/zip installation, full Jinja2, LDAP, and Apprise remain unimplemented.
The API table records those limits and was regenerated only after reviewing the
curated deltas and generated diff.

## Verification

- Host standalone suite: 1350 passed, 1 skipped, 0 failed; 223 fuzz tests discovered.
  The skip is the gated real-Klippy proxy test. New regression tests cover cache
  restoration, fixed-cadence sampling and partial readings, HTTP transport gating,
  database policies and parent directories, config webcam persistence, public
  error messages across transports, and OctoPrint state/temperatures.
- API surface: 123/123 static endpoints, 130/130 methods, 27/27 notifications,
  overall 100%. Scanner tests: 72 passed.
- Static ARM ReleaseSafe binary ran inside the Forge-X 1.4.2 chroot on
  `127.0.0.1:7126`, using a refreshed database copy. Compared 32 read-only paths
  with Moonraker on 7125, checked WebSocket info and heater queries on both,
  and completed 80 proxy reads across four clients without hangs.
- Printer info, object lists, canonical file roots, webcams, announcements,
  job queue, history totals, and OctoPrint state/settings/temperatures matched.
  The configured component set contained the same 26 names. Database namespace
  sets matched. Update status matched apart from the newer upstream git `name`.
- At the default capacity, every temperature field grew from 215 to 255 samples
  over 40 seconds. A separate probe with capacity 3 filled all four sensors and
  stayed capped across five further timer ticks, with heater targets/powers zero.
- Probe stopped, with no listener on 7126. Moonraker remained ready on 7125 and
  both heater targets remained zero. The board boot ID was unchanged, and the
  live database retained its original size and modification time.

## Retained differences

| Classification | Difference and reason |
| --- | --- |
| Code bugs, fixed | Sparse temperature arrays, missing cached update state, incorrect git version formatting, invented `repo_detected`, unconfigured updater objects, websocket-only HTTP 405, private/empty database namespaces, config webcam persistence, and stale OctoPrint state/temperatures. |
| Identity, kept | phobos reports API 1.5.0 and `moonraker_version: phobos`; the printer reports 1.4.0 and `?`. The OctoPrint version text also reflects phobos's compatibility version. Downgrading would misidentify the implementation. |
| Identity, kept | Git status retains `name`, emitted by the pinned upstream `GitDeploy.get_update_status`; Forge-X's older API omits it. |
| Identity, kept | Python version fields remain the explicit stub. phobos does not claim to run CPython 3.11.10. |
| Identity, kept | Missing `can0` returns an empty `can_uuids` list rather than the printer's 500. Error responses omit Python tracebacks. Public required-argument and missing-namespace messages and error codes match. |
| Environment | Component and namespace ordering, websocket counts, gcode history, and temperature history age differ between independently started processes. The printer already has 1200 samples; a new probe accumulates its own history. |
| Environment | Forge-X does not load analysis, notifiers, sensors, spoolman, device_power, WLED, TD-1, or debug database routes. Its 404 responses are expected; `registerAll` retains those implementations. |

The probe is temporary and is not installed as the printer's Moonraker. No print,
motion, heating, firmware restart, service restart, update, package installation,
board reboot, or shutdown was requested. Machine reboot/shutdown stay deliberate
no-ops. The live database, printer configuration, and golden images were not
opened by phobos or modified by the checks. No emulator was started.
