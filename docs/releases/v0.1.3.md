# phobos v0.1.3

Released 2026-10-20. Uses Zig 0.17 standard I/O for clocks, secure randomness,
directory creation, socket addresses, DNS, interruptible timers, and SQLite
read-modify-write locking. Existing symlinked data roots and database parents
open through `std.Io.Dir.createDirPathOpen`. File-backed namespaces use
`std.Io.File.Atomic` with sync before replacement.

Print statistics now own their JSON snapshots, merge partial updates, and expose
an atomic printing flag to background update checks. The Klippy handshake seeds
that cache without replaying old job events. Heater subscriptions preserve the
base print-state subscription. Background Klippy notifications run under Core,
request waits support cancellation, and Feather replies no longer acquire the
same write lock twice.

WebSocket clients validate the upgrade, use secure nonce and mask bytes, handle
fragmented messages and interleaved ping frames, and read messages beyond the
receive buffer without asserting. Spoolman URLs use `std.Uri`, retain path
prefixes, accept IPv6, and use verified TLS for HTTPS/WSS. MQTT and WebSocket
clients share the heap-stable standard TLS client state. Moving an MQTT client
preserves bytes buffered with CONNACK. Owned futures cancel stalled Klippy, MQTT,
Spoolman, announcement, and queued-dispatch workers before freeing their state.

Allocation failure and replacement paths now release partial owned state across
startup, authentication, webcams, devices, buttons, sensors, TD1, agents, WLED,
file filters, and queued/history fields. JSON copies release partial trees.
Numeric request fields reject overflowing float conversions, configuration
floats reject non-finite values, and WLED updates bound work by the supplied
pixel buffer. Unused reflection-based parameter coercion was removed.

## Verification

- Host suite: 1410 passed, 1 skipped, 0 failed; 236 fuzz tests discovered.
  The skip is the host real-Klippy test, whose local socket is absent.
- Regression coverage includes allocation failures, freed input arenas, partial
  print updates, stalled handshakes, fragmented WebSockets with masked pong,
  certificate and hostname verification, buffered MQTT traffic, IPv6 listeners,
  symlinked startup paths, extreme numeric values, and spurious timer wakes.
- Static ARM ReleaseSafe probe inside the Forge-X 1.4.2 chroot, bound exclusively
  to `127.0.0.1:7126`, uses the copied database. Read-only HTTP and WebSocket
  proxy requests succeed against the real Klippy socket. Directory listings,
  file roots, and one-second temperature sampling are checked on ARM.
- API coverage: 123/123 endpoints, 130/130 methods, 27/27 notifications.
  Generated coverage documents were not regenerated. Graphify was skipped
  because its executable is unavailable.
- The probe is stopped after verification. Production phobos on 7125 is not
  replaced by this release. No board restart, motion, heating, print start,
  firmware restart, or update operation was performed.

## Retained differences and native exceptions

API 1.5.0 and `moonraker_version: phobos` identify this implementation and its
vendored API pin; Forge-X's older API 1.4.0 is not a compatibility target for
those identity fields. The Python version remains an explicit stub. Missing
CAN interfaces still return an empty UUID list. Optional components remain
available when registered; the real Forge-X configuration selects its component
set. Host OS, CPU, and network differences are environmental; ARM checks run
inside the real Forge-X chroot.

Zig 0.17 has no filesystem-capacity operation or WebSocket client. The musl
`statvfs` shim and bounded client frame codec remain. Typed platform operations
remain for inotify, serial termios, system identity, and video ioctls. SQLite's
C binding remains required for its storage format. Full Jinja2, LDAP, and
Apprise remain outside scope; `klipper_estimator` requires an injected shell.
