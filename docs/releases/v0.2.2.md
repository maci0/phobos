# phobos v0.2.2

Released 2026-10-21. This patch reduces temperature/history allocations and
preserves unfinished jobs when reading migrated Moonraker history. Zig 0.17.0,
SQLite 3.54.1 and Moonraker reference pin `900848584374` are unchanged.

## Changes

Temperature history allocates storage only for fields a heater or sensor
actually reports. Sampling cadence and response fields are preserved.

Unfiltered SQLite history queries select and paginate scalar IDs before
decoding job metadata. KV records still override legacy table rows.
Noncanonical keys, non-object records and time filters retain the namespace
fallback. JSON is validated on actual KV rows, and selected values own their
decoded strings without retaining a second encoded copy. Legacy rows reuse
one prepared lookup per page and reserve their known JSON field count. KV
keys are formatted only for selected jobs; SQLite's existing key index excludes
shadowed legacy IDs without a duplicate in-memory hash map. SQL null end times
remain null, preserving unfinished jobs and time-filter behavior.

The native request-arena key-index fixture falls from 186,830 to 43,992 bytes
(76.5%). The separate 200-row legacy fixture falls from 858,758 to 517,988 bytes
(39.7%). These are allocation fixtures, not process-RSS savings. Matched host
and printer results include CPU, latency and RSS regressions; no uniform speedup
is claimed. [Memory](../MEMORY.md) and [performance](../PERFORMANCE.md) contain
methods, full ranges, executable/seed hashes and metric directions.

Profiling elevates only counter collection; the measured daemon remains
unprivileged. CI now verifies all seven static Linux profiles, complete native
x86-64/AArch64 suites, native release-asset smoke tests and the assembled bundle
before publishing a tag. Uploaded assets are downloaded and verified before
the draft release becomes public. See [CI.md](../CI.md).

## Verification and binaries

Pre-release source validation passes 1,730 tests in both Debug and ReleaseSafe,
with one gated real-Klippy skip, zero failures and 326 bounded fuzz harnesses.
API coverage remains 123/123 endpoints, 130/130 methods and 27/27 notifications;
the generated coverage table is current. The unchanged external golden-replay
limitations remain recorded in [v0.2.0](v0.2.0.md).

The latest three tuning rounds include 102 host trials and 36 Forge-X printer
trials, all requests successful. All 84 physical history comparisons match,
including mixed KV/table history and wide IDs. Those tests used copied data on
loopback port 7126, with production v0.2.1 unchanged and no printer-control
commands. Their recorded versions and hashes remain attached to the captures.

Seven static musl ReleaseSmall assets cover ARMv6 hardfp, ARMv7 software float,
ARMv7 mixed C softfp, ARMv7 hardfp, Cortex-A7 hardfp, AArch64 and x86-64.
[BUILDS.md](../BUILDS.md) lists their requirements and asset names. The mixed
softfp profile retains C hardware arithmetic, Zig software arithmetic and
disabled LTO; other profiles retain full LTO. Cross-building an asset does not
certify a different physical printer or CPU.

## Retained behavior and limits

API 1.5.0 and software version `phobos` identify this implementation rather than
imitating Forge-X's API 1.4.0 and unknown Moonraker version. Python version
fields remain a stub. CAN discovery returns an empty list when the interface
is missing. Optional components remain available when registered even if a
Forge-X configuration omits them. Reboot and shutdown remain no-ops.

Full Jinja2, real LDAP and real Apprise remain outside scope;
`klipper_estimator` requires an injected runner. Filtered/unlimited history can
still decode the full namespace, and the scalar index grows with total job
count. Long-soak and dedicated-host performance are not established. Other
limits remain in [TODO.md](../../TODO.md).
