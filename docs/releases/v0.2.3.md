# phobos v0.2.3

This release reduces large JSON decoding, SQLite preparation, filesystem
checks and console snapshot allocations. Zig 0.17.0, SQLite 3.54.1 and the
Moonraker reference pin `900848584374` are unchanged.

## Changes

Fluidd subscriptions accept its response-template parameter and database keys
sent as arrays. Console status delivery batches a Klippy update before filtering
each client's requested objects and fields. Large replies are parsed once and
retain their arena until the waiter copies them. A 64 KiB standard Klippy
reader and vectored socket writes reduce small copies and writes. Legacy
history without KV overrides selects the requested SQL page directly, while
mixed and filtered histories keep their validated fallback.

Long ASCII JSON string values use bulk copies and portable Zig vectors while
the standard parser retains structure, keys, numbers, Unicode and short-input
handling. Klippy response arenas retain ownership through delivery. SQLite
records decode directly into the request arena, and response strings write
into standard buffered-writer capacity.

SQLite reuses namespace-list and table-existence statements under the existing
store lock. Results remain fresh after writes and schema changes. History file
checks use checked metadata rather than opening file contents. Console snapshots
allocate only the requested entries, preserving wrapped FIFO and count semantics.
Entry maps reserve exactly their three fields. Allocation regression fixtures
bound a one-entry snapshot to 8 KiB and a full 1,000-entry snapshot to 512 KiB.

The owned standard I/O backend uses 1 MiB worker stacks on all architectures and
passes the actual startup environment to child processes. This reduces native
stack reservations and prevents missing child environment variables on ARM32.
Seven static musl profiles now use ReleaseFast. The mixed C softfp profile keeps
its documented software-float Zig code and disabled LTO. See [builds](../BUILDS.md).

## Verification and measurements

All ten profiling rounds are recorded, including rejected variants and paths
where no further source change was justified. Fresh release-binary measurements,
metric directions, trial ranges and remaining performance gaps are in
[performance](../PERFORMANCE.md) and [memory](../MEMORY.md). Profiling timings
are diagnostic and are kept separate from uninstrumented comparisons.

The complete Debug, ReleaseSafe and ReleaseFast suites each pass 1,768 tests,
with one gated local real-Klippy skip, zero failures and 335 fuzz tests.
All 110 Python tooling tests and four build-policy tests pass. Registration
coverage remains 123/123 endpoints, 130/130 methods and 27/27 notifications;
the generated API table passes its freshness check without regeneration.
The MQTT reconnect test waits for broker receipt before its exact subscription
count assertion; a connection callback alone does not prove socket draining.
Physical-printer checks and publication evidence are recorded in the release
verification captures. [CI](../CI.md) validates all seven profiles and native
x86-64/AArch64 suites before publishing verified assets.

Two isolated KVM studies complete 72 trials and 959,968 successful requests.
The printer completes 24 HTTP trials with 10,440 successful requests, 126 full
subscriptions and 36 matching history comparisons. Phobos has lower median p99
and sampled RSS in every measured HTTP case. Remote large-config CPU remains 2.0%
higher than Moonraker; all other HTTP workload CPU medians favor phobos. Scheduling
delays and full trial ranges remain visible. These are fixed-arrival results,
not maximum-throughput claims.

All five ARM32 daemon assets pass real Klippy, 262-object subscriptions, all
26 production components, directory capacity, private Fluidd array keys,
history and advancing temperature stores inside the Forge-X chroot. All five
also pass C/Zig floating-point probes. No hardware command is issued.

## Retained behavior and limits

API 1.5.0 and software version `phobos` identify this implementation. Forge-X's
API 1.4.0 and unknown Moonraker version are identity differences. Python version
fields remain a stub. Missing CAN interfaces return an empty discovery list.
Optional components remain available when registered. Reboot and shutdown
remain no-ops. Full Jinja2, real LDAP and real Apprise remain outside scope;
`klipper_estimator` requires an injected runner.

Fixed-arrival benchmarks do not establish maximum capacity or superiority on
every printer. Fixed frequency, literal zero scheduling delay, long-soak and
printing/upload performance are not established. Other limits remain in
[TODO.md](../../TODO.md).
