# phobos v0.4.1

This patch release fixes stale Git update status and the release upload that
kept v0.4.0 from being published. It is the first published release with the
[v0.4.0 changes](v0.4.0.md): the AD5X MIPS profile, Moonraker ZIP packages and
the printer installation guides. Zig 0.17.0, SQLite 3.54.1, and the Moonraker
reference pin `900848584374` are unchanged.

## Changes

`/machine/update/status` and `/machine/update/refresh` returned Moonraker's
cached `update_manager` database record for a Git source whenever one existed.
Phobos never rewrites that record, so after a fetch or an update the response
kept the old hashes and reported zero commits behind. For a readable repository
the branch, versions, hashes, dirty and detached state and the commits-behind
list now come from the repository on every status request. `rollback_version`
and the remaining cached fields are unchanged, and an unreadable repository
still returns the cached record. See [software updates](../UPDATES.md).

The release workflow uploaded only `phobos-v*` files, which left the
`phobos-<target>.zip` packages out of the draft while `SHA256SUMS` listed them.
Verification of the uploaded draft failed and v0.4.0 stayed a draft with no
published assets. The workflow now uploads the ZIP packages too.

## Verification

The test suite passes in Debug, ReleaseSafe, and ReleaseFast modes: 1,805 passed,
one gated real-Klippy skip, zero failures, and 343 bounded fuzz tests per mode.
A new test builds a local repository behind its origin with a stale cached
record and checks the status response; it failed before the fix.

The status fix has not been run on a printer. The stale status was observed on
an AD5M running Forge-X 1.4.2 with phobos v0.3.0; see
[provenance](https://github.com/maci0/phobos/blob/main/docs/PROVENANCE.md).

## Retained behavior and limits

The limits listed for [v0.4.0](v0.4.0.md#retained-behavior-and-limits) apply
unchanged. A status request for a Git source with a cached record now runs local
Git commands instead of reading only the database.
