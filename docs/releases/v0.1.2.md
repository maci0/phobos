# phobos v0.1.2

Released 2026-10-19. Fixes the ARM crash triggered when Fluidd opens a file
directory. The old raw `statfs` call used a 64-bit Linux structure on the
printer's 32-bit ARM CPU, causing an integer-overflow panic. Disk usage now
uses musl's `statvfs` through its platform header. The installed Zig 0.17.0
`std.Io` has no filesystem-capacity operation. Used space excludes reserved
free blocks, matching `shutil.disk_usage`.

Extended gcodes directory listings include metadata through the existing bounded
cache, preserving basenames in subdirectories. Non-extended listings and other
roots retain their stat-only fields. Metadata reads the first 256 KiB of large
files with `std.Io.File.readPositionalAll`; the previous reader rejected files
larger than that limit. OrcaSlicer total-layer declarations and durations such as
`1h 16m 59s` now parse correctly.

## Verification

- Reproduced the original panic inside the Forge-X 1.4.2 chroot with an ARM
  Debug binary and a directory request before changing the implementation.
- Regression tests cover disk byte counts and missing paths, extended metadata,
  nested basenames, large-file header/footer reads, OrcaSlicer layer counts, and
  duration units. The extended-listing, large-file, and OrcaSlicer tests failed
  before their respective fixes. Bounded fuzz tests exercise file prefixes,
  disk paths, duration fields, and handler parameters.
- Host standalone suite: 1358 passed, 1 skipped, 0 failed; 226 fuzz tests found.
  The skip remains the gated real-Klippy proxy test.
- API coverage remains 123/123 endpoints, 130/130 methods, 27/27 notifications.
  Generated API coverage documents were not changed. Graphify was skipped because
  its executable is unavailable.
- Static ARM ReleaseSafe binary passed 120 extended directory requests across
  four clients, split between HTTP and WebSocket, on `127.0.0.1:7126` using the
  copied database. Disk counts matched the printer's `df` output. Fluidd 1.37.7
  rendered its dashboard, jobs, configuration, and system pages.
- The printer's Benchy metadata reports OrcaSlicer 2.4.2, 240 layers, and 4619
  seconds. Fluidd displays the parsed slicer fields and print estimates.

## Printer deployment

After explicit approval to replace the crashed server on 7125 and use the normal
database, the database, WAL/SHM files, and previous launcher were copied to
`/data/phobos-backups/v0.1.2-20261019/` while Moonraker and the production phobos
were stopped.
The existing `/data/phobos-run.sh` launcher now runs `/data/phobos-v0.1.2`.
Init scripts and printer configuration were not edited.

The crash fix serves `0.0.0.0:7125` inside the chroot. Fluidd connects to that
address, and another 120 concurrent HTTP/WebSocket directory checks passed there.
The temporary 7126 probe is stopped. At deployment verification, Klippy was ready,
the printer was in standby, and both heater targets were zero.

The user then started a Benchy print through phobos. The running process was left
in place. The final release binary includes an additional correction for estimates
expressed only in minutes, such as `16m`; it is installed for the next process
start and was not activated during the print. That correction passed host unit
and fuzz tests and the full suite. The board boot ID is unchanged. No print,
motion, heating, Klipper restart, firmware restart, remote update, reboot, or
shutdown was requested by the verification checks. Reboot persistence and print
completion were not tested.

## Retained differences

The [v0.1.1 compatibility distinctions](v0.1.1.md#retained-differences) remain:
API 1.5.0 and `moonraker_version: phobos` identify this implementation; Python
version fields remain a stub; missing `can0` returns an empty list; optional
components remain available when registered. Host hardware and independently
accumulated history are environmental differences. Full Jinja2, LDAP, and Apprise
remain out of scope; estimator execution still requires an injected shell.
