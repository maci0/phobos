# phobos v0.2.1

Released 2026-10-21. SQLite advances to 3.54.1, the stable upstream release
dated 2026-10-16. The tracked amalgamation is unmodified; its source ID,
download URL and verified archive/file hashes are in
[the dependency manifest](../../vendor/sqlite/README.md).
The Zig 0.17.0 compiler and Moonraker reference pin `900848584374` are unchanged.

## Linux binaries

Seven static musl ReleaseSmall profiles cover ARMv6 hardfp, ARMv7 software
float, ARMv7 mixed C softfp, ARMv7 hardfp, Cortex-A7 hardfp, baseline AArch64
and baseline x86-64. The existing Cortex-A7 asset filename is retained.
[BUILDS.md](../BUILDS.md) lists CPU/kernel requirements, common host examples,
asset names and the reproducible ELF/ABI/checksum validation command.

The softfp option applies to the C sources; Zig retains software arithmetic
under `musleabi`. Full LTO is disabled for this mixed profile because the
pinned compiler changes the C floating-point calling convention during LTO.
The hardware check caught zero-valued SQLite REAL history columns before
publication. A repeatable C/Zig floating-point ABI probe covers the corrected
build. Other profiles keep full LTO.

## Verification and measurements

The complete standalone Debug suite passes 1718 tests, with one gated
real-Klippy skip, zero failures and 325 bounded fuzz harnesses. The test-server
constructor now waits for the bridge's proxy gate as well as the simulator
handshake, fixing a fixture race exposed by the first complete run.
Four build-policy tests, including two bounded fuzz tests, and all 100 Python
scanner/measurement tests pass. Shell helper smoke checks, Ruff, Black and
the changed Python tools' type checks pass.

API registration coverage remains 123/123 literal endpoint paths, 130/130
JSON-RPC methods and 27/27 notifications. A fresh dump and all generated API
and client tables are unchanged. Documentation now distinguishes registration
coverage from implementation behavior, target execution and hardware support.
The client matrix retains its nine plugin/nonstandard gaps. The historical
external golden replay's seven differences are recorded in
[v0.2.0](v0.2.0.md); that capture was not rewritten.

[Performance](../PERFORMANCE.md) and [memory](../MEMORY.md) contain fresh,
versioned host and printer measurements. The host comparison runs full pinned
Moonraker and the portable x86-64 release asset against the same Klippy stub
and read fixture. The printer comparison runs published v0.2.0 and the exact
v0.2.1 Cortex-A7 asset sequentially on port 7126 with independent database
copies. All 42 printer trials completed without failed requests. Plots read
measured JSON rather than hardcoded historical values. The report formatter
also accepts the actual Vegeta percentile keys, covered by a regression test.
Every figure labels whether higher or lower is better. Tables distinguish
matched-load results from unlimited throughput and identify the measured
host winner; the short printer comparison has no clear overall winner.

The physical probe used the Forge-X 1.4.2 chroot on a two-core Cortex-A7,
Linux 5.4.61. All five ARM32 assets passed startup, real object queries,
directory statistics and identical copied SQLite floating-point history/totals
reads after the softfp correction. The
[asset-specific smoke record](../perf/arm32-smoke-v0.2.1.json) records their hashes.
ARM32 execution there does not certify an ARMv6 board or another
printer model. AArch64 was cross-built and ELF-checked, without execution on
64-bit hardware. No QEMU was used.

Production remains v0.2.0 on port 7125. The probe uses copied data, is stopped
after verification, and is not installed as the production service. Heater
targets remain zero, Klippy is ready and the board boot ID is unchanged.
No motion, heating, print start, Klipper restart, firmware update or board
reboot was requested. The live database and printer configuration were not
opened for modification.

## Retained behavior

API 1.5.0 and software version `phobos` identify the implementation. They do
not imitate Forge-X's older API 1.4.0 or unknown Moonraker version. The Python
version fields remain a stub rather than claiming CPython 3.11.10.

CAN discovery keeps an empty list when the interface is unavailable. Optional
components remain implemented when registered even if a Forge-X configuration
omits them. Reboot and shutdown remain no-ops. Full Jinja2, real LDAP and real
Apprise stay outside scope; `klipper_estimator` requires an injected runner.
Other documented behavior limits remain in [TODO.md](../../TODO.md).
